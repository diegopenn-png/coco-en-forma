PRUEBA LOCAL SIN SUSTITUIR PRODUCCIÓN
-------------------------------------
1. Descomprime Coco-en-Forma-v144.0.zip en una carpeta vacía.
2. No mezcles sus archivos con la carpeta pública existente.
3. Abre una terminal dentro de la carpeta descomprimida.
4. Ejecuta:

   python3 -m http.server 8080

5. Abre en el navegador:

   http://localhost:8080/

No abras index.html mediante file:// porque el service worker y algunas funciones PWA necesitan un origen HTTP. localhost se considera un contexto seguro para estas pruebas.

MIGRACIÓN OPCIONAL DE SUPABASE
------------------------------
La aplicación puede probarse localmente sin migrar la base; el runner guarda respaldo local.

Para persistir el historial personal del runner en cuentas autenticadas:
1. Realiza primero una copia de seguridad de Supabase.
2. Revisa supabase-coco-v144.sql.
3. Ejecútalo una sola vez en el SQL Editor del proyecto de prueba.
4. Comprueba que cada usuario solo puede ver e insertar sus propias filas.

No es necesaria una migración nueva para Coco Pádel: la v144 reutiliza la tabla existente coco_padel_club_state y normaliza el estado guardado.

RESTAURACIÓN DE ARCHIVOS
------------------------
Si se decide descartar la v144:
1. Detén el servidor local de prueba.
2. Elimina únicamente la carpeta aislada de la v144.
3. Conserva o vuelve a descomprimir Coco-en-Forma-v143.0-copia-intacta.zip.
4. No copies archivos de la v144 sobre la v143.

RESTAURACIÓN DE BASE DE DATOS
-----------------------------
No ejecutes el rollback salvo que hayas aplicado la migración v144 y aceptes borrar el historial personal creado por Coco Corre.

supabase-coco-v144-rollback.sql elimina exclusivamente public.coco_runner_history. No afecta partidas, perfiles, clasificaciones ni Coco Pádel.
