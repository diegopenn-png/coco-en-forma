COCO EN FORMA v149.0 — RESPALDO, PRUEBA Y RESTAURACIÓN
=======================================================

IMPORTANTE
----------
Esta entrega no ha sido publicada ni desplegada. No sustituya la aplicación pública
hasta haber probado y aprobado expresamente la v149.0.

NO SUBA EL ZIP COMO ÚNICO ARCHIVO A GITHUB
------------------------------------------
Para servir la aplicación desde GitHub, descomprima el ZIP y suba el CONTENIDO de la
carpeta Coco-en-Forma-v149.0 conservando exactamente todas las carpetas y nombres.
El archivo index.html debe quedar en la raíz publicada junto a sw.js, los módulos,
manifest.json, share/, juego/, scenes/ y el resto de recursos.

No es necesario conservar dentro de la web la carpeta de copia base-v1480; esa copia
se entrega por separado en el espacio de trabajo y no forma parte del ZIP público.

RESPALDO ANTES DE PROBAR
------------------------
1. Descargue o clone la versión pública actual completa.
2. Guarde una copia fuera de la carpeta que vaya a modificar.
3. Exporte la base de datos de Supabase o cree un backup desde el panel.
4. Si es posible, restaure ese backup en un proyecto Supabase de pruebas.
5. Anote las variables y políticas RLS actuales antes de realizar cambios.

PRUEBA LOCAL SIN SUSTITUIR LA WEB
---------------------------------
1. Descomprima Coco-en-Forma-v149.0.zip en una carpeta nueva.
2. Abra una terminal en la carpeta que contiene Coco-en-Forma-v149.0.
3. Ejecute:

   python3 -m http.server 4173 --directory Coco-en-Forma-v149.0

4. Abra http://localhost:4173/ en una ventana privada.
5. En DevTools > Application, desregistre cualquier service worker anterior asociado
   a localhost si fuera necesario y recargue.
6. No copie estos archivos sobre la carpeta pública durante la prueba.

BASE DE DATOS DE PRUEBAS
------------------------
Para verificar que Coco Corre puntúa realmente, aplique primero
supabase-coco-v149.sql en una COPIA de Supabase. La migración:

- no borra datos;
- respalda las restricciones anteriores;
- acepta cococorre como juego válido;
- crea registrar_coco_corre_v149(integer);
- limita esa función a usuarios autenticados y una escritura diaria.

Si necesita revertir la estructura, ejecute supabase-coco-v149-rollback.sql. La
reversión restaura las restricciones guardadas y no borra partidas ya registradas.
